Rooms have a lead, and records of their own. With the directory on (`builtin:directory`), every room is led by the agent you choose on its page, else the one the plugin's new `leads` config names (`leads: { travel: trip-planner }`, by room name or ref), else the agent that created it. A room keeps a profile (what it's for, seeded from its purpose, plus a note for people), commitments and docs, in its own scope. Agents in the room, and the lead, change them with the tools they already have by naming the room (`commitment open room: travel`, `writeup write room: travel`, `directory profile|page room: travel`), and `directory about room: travel` reads one. Each update on a room's commitment says who wrote it. An agent that isn't in the room is refused in one sentence, and doesn't see the room's commitments, docs or misses at all; the room's profile is every agent's to read.

A person's edit to a room's record stays as they left it: an agent that tries to change a field a person set is told so ("A person set nextStep on …, so it stays as they left it. Ask them if it should change."), and the rest of the record stays the members' to change. Creating a record isn't an edit, and clearing a field hands it back. The rule is read from the record's history, so it covers edits on the State page too.

Hand it something on a room's page opens a commitment for the room's lead, from you, naming the room; the lead sees it in its "Your commitments" block as "for the travel room". The lead's upkeep turn gains a section for each room it leads, counted by the same rules as its own records, and what it changes there counts in its "Last upkeep" line.

The web UI gains a Rooms page (`#/rooms`): every live room with its purpose, lead, members and how much it has open and waiting, and a page for each with what it's for (editable), the lead and members (with a choice to change the lead), working on, waiting on you, recent results, docs, questions nobody could answer, and a form to hand its lead something. Fields a person set are marked "set by you". New routes: `GET rooms`, `GET rooms/:room`, `POST rooms/:room/commitments`, `PUT rooms/:room/lead`, `PATCH rooms/:room/profile` and `PATCH rooms/:room/commitments/:id`, under `/api/ext/builtin:directory/`. An agent's page names the rooms it leads.

Behaviour you may notice: the directory's tools now show an agent the commitments and docs of every room it's in, wherever its turn is (its upkeep, a direct message, another room), rather than only in a turn woken in that room. The `state` tool keeps world state's rule unchanged. Searches can now find room records for their members, and a search nobody answers can be noted against a room whose profile is closest. A room's profile is a `profile` record with `owner: "room:<ref>"`; the agent list leaves those out.
